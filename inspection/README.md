# 여의도 도로망 검수 도구

`env/yeouido/yeouido.net.xml`(SUMO 도로망)이 실제 도로와 맞는지 눈으로 확인하고 기록하는 도구.
노드링크 원본의 위치 오차 때문에 사진 위에 겹쳐 보는 방식은 쓰기 어려워서,
**카드 하나씩, 왼쪽 SUMO 그림 · 오른쪽 항공사진을 나란히** 놓고 구조를 비교한다.
카드는 SUMO 도로망의 두 구성 요소에 맞춰 두 종류다.

| 카드 | SUMO | 개수 | 보는 것 |
|---|---|---|---|
| 교차로 | junction | 395 (갈림·합류가 있는 곳만) | 진입로별 차로 수·차로별 회전 방향 (그 자리에서 고침), 신호, 진입로 구성 |
| 도로 구간 | edge | 1,612 | 교차로 사이 한 방향 도로의 차로 수, 모양·위치, 앞뒤 연결, 노드링크 원본 값과 비교 |

## 준비 (한 번만)

```bash
source .venv/bin/activate              # yeouido/requirements.txt 설치된 환경
echo "VWORLD_API_KEY=발급받은키" > .env  # vworld.kr 인증키 (WMTS/TMS)
```

## 실행

```bash
python -m inspection.serve      # http://127.0.0.1:8765 이 브라우저로 열림
```

| 화면 | 주소 | 용도 |
|---|---|---|
| **검수 카드** | `/` | 검수 (SUMO ↔ 항공사진 나란히 비교, 기록). 위쪽에서 교차로 / 도로 구간 전환 |
| 전체 지도 | `/viewer.html` | 항공사진 + SUMO 차로·연결 + 국가표준노드링크 겹쳐 보기 |

도로망·노드링크가 바뀌면 서버를 다시 켤 때 `inspection/out/` 자료가 자동으로 다시 만들어진다.

## git에 올리기 전
```bash
python -m yeouido.run_all --skip-validate
```
region.json과 correction.json 파일 합쳐서 맵 제작 진행된다.



## 검수 방법


1. 가운데 두 화면: 왼쪽은 SUMO 도로망을 sumo-gui처럼 그린 것(실제 폭의 차로, 차선, 교차로,
   차로 끝 회전 화살표, 교차로 안 경로), 오른쪽은 항공사진.
   - 이동·확대가 같이 움직이고, 마우스를 올린 곳이 반대편에 노란 십자로 표시된다.
   - 진입로 글자(A, B, …)가 양쪽에 같이 찍혀 있다. SUMO 쪽 차로를 누르면 도로명·차로 수·차로 끝 방향이 나온다.
   - **위치 맞춤**: 노드링크 원본이 실제보다 수 m 밀려 있어, 사진 쪽을 교차로마다 보정값만큼 옮겨
     양쪽 가운데에 같은 교차로가 오게 한다 (도로망 파일은 그대로). 자동값은 항공사진과 잘 맞는
     OSM 도로선에 맞춘 것(교차로 395개 중 352개). 덜 맞으면 사진 왼쪽 아래 화살표나
     `Shift+방향키`로 0.5 m씩 옮기고, 옮긴 값은 기록에 저장된다.
2. 오른쪽 카드의 같은 글자와 비교한다: 사진의 정지선 앞 차로 수·노면 화살표 = SUMO 차로·화살표?
   (카드는 운전자 시점, 노란 선 = 중앙선 쪽)
   - 다르면 그 진입로 칸에서 바로 고친다 (아래 "도로망 고치기").
3. 교차로 전체의 신호 유무와 진입로 구성(빠진 길·없는 길)을 확인한다.
4. **정상 / 문제 / 보류**를 누르고, 문제면 메모에 무엇이 다른지 적는다.
   - **정상**을 누르면 바로 다음 카드로 넘어간다.
   - **문제·보류**로 판정한 카드는 이름·판정·검수자·메모가 `inspection/issues.md` 에 따로 모인다
     (기록할 때마다 다시 씀, 판정을 바꾸면 빠짐).

### 도로망 고치기 (버튼·단축키)

| 어디서 | 무엇을 | 버튼 | 키 |
|---|---|---|---|
| 교차로 카드 진입로 | 정지선 차로 하나의 좌회전·직진·우회전 켜고 끄기 | 차로 아래 `좌` `직` `우` | 진입로 `↑` `↓`, 차로 `,` `.`, 방향 `Q` `W` `E` |
| 교차로 카드 진입로 | 좌회전·우회전 포켓 추가·제거 (정지선부터 잰 길이) | 추가 / 제거 | `Shift+Q` / `Shift+E` |
| 교차로 카드 진입로 | 그 도로 전체 차로 수 | `−` `+` | `-` `=` |
| 교차로 카드 진입로 | 노드링크 회전 제한(금지) 지우기 / 되돌리기 (실제로는 갈 수 있을 때) | "노드링크: …금지" 줄의 지우기 | |
| 도로 구간 카드 | 그 도로 전체 차로 수 | `−` `+` | `-` `=` |
| 도로 구간 카드 | 실제로 없는 도로 삭제 / 되살리기 (이 방향만) | 삭제 / 되살리기 | `Delete` |

- 차로 수를 바꾸거나 포켓을 넣으면 중앙선 쪽 가장자리는 그대로이고 바깥쪽(인도 쪽)으로만 넓어지거나 좁아진다.
- 고친 곳(그 도로와 그 도로 앞 교차로로 들어오는 길)의 차로 연결은 늘 정리된다: 엇갈리지 않게, 도착 차로가 넉넉하면
  하나씩 나눠서 (신호 없는 합류는 순서만). 방향을 켜면 가장 가까운 옆 차로가 가는 도로로만 잇는다.
- 누르면 화면에 바로 보이고, 0.9초 동안 더 누르지 않으면 모아서 `yeouido/corrections.json` 에 적고
  수정 후 도로망을 다시 만든다 (5~10초, 결과는 위쪽 줄). 왼쪽이 "수정 후"로 바뀐다.
- 고친 진입로는 "원래" 차로와 "수정 후 정지선 차로"가 같이 나온다. 차로 번호 0 = 맨 오른쪽.
- 차로 방향은 그 진입로에서 원래 갈 수 있던 곳 안에서만 늘린다. 그 방향 길이 없으면(회전 금지 등) 이유만 나오고
  목록에 남지 않는다. 도로가 짧은 포켓, 랜드마크 도로 포켓도 같다.
  그 방향으로 가던 마지막 차로에서 빼면 그 회전은 없어진다 (실제로 못 가는 회전일 때).
  같은 좌회전이라도 갈 수 있는 도로가 둘 이상이면 버튼으로는 구분이 안 되므로, `corrections.json` 의 그 `lane_moves` 항목에
  `"to": ["도착 도로 ID"]` 를 직접 적어 그 도로로만 가게 한다.
- 차로 수나 포켓을 바꾸면 차로 번호가 달라지므로 그 도로의 차로 방향 수정은 지워진다 (위쪽 줄에 안내).
  방향은 차로 수·포켓을 먼저 정한 뒤 고친다. `Backspace` = 고른 진입로의 차로 방향 수정 모두 지우기.
- 단축키는 한/영 상태와 상관없이 같은 자리 키로 동작한다. 전체 목록은 `?` (`Shift+/`) 또는 위쪽 "단축키" 버튼.
- env 도로망은 그대로다 (반영은 아래 "도로망 수정" 참고).

도로 구간 카드는 화면에 도로 전체가 보이게 맞춰지고, 그 도로의 차로가 노란 테두리, 시작·끝이
양쪽 화면에 표시된다. 카드에는 SUMO ↔ 노드링크 원본 비교표(차로 수·제한속도·도로명, 다르면 빨간색),
차로별 끝 방향, 시작·끝 교차로, 반대 방향 도로가 나온다.
확인 항목은 **차로 수**, **도로 모양·위치**(실제 도로를 따라가는지), **앞뒤 연결**(끊기거나 없는 연결).

두 카드는 서로 이어진다: 교차로 카드의 진입로·나가는 길 → "도로 카드", 도로 카드의 시작·끝 → "교차로 카드",
SUMO 화면에서 차로를 누른 정보창 → "도로 구간 카드". 주소 `#j:<교차로 ID>`, `#r:<도로 ID>` 로 바로 열 수 있다.

| 키 | 동작 |
|---|---|
| `←` `→` | 이전 / 다음 카드 |
| `1` `2` `3` | 정상 / 문제 / 보류 |
| `A` | 위치 맞춤 켜고 끄기 |
| `V` | 왼쪽 SUMO: 원래 ↔ 수정 후 |
| `?` | 단축키 전체 보기 (도로망 고치기 키는 위 표) |
| `Shift` + 방향키 | 사진 쪽 위치를 0.5 m씩 옮기기 (⟲ 버튼 = 자동값으로 되돌리기) |

자동 점검 힌트(빨간 숫자):
- 교차로: 노드링크 회전 제한과 다른 연결, 갈 곳 없는 차로, netconvert 경고.
  U턴 힌트는 참고용이다 (`yeouido/build_net.py` 가 `--no-turnarounds` 로 U턴을 모두 뺐다).
- 도로 구간: 노드링크 원본과 다른 차로 수·제한속도, 끝에서 갈 곳 없는 차로, netconvert 경고,
  (참고) 직진으로 이어지는 다음 구간과 차로 수 2개 이상 차이, 5 m 미만 구간.



## 도로망 수정 (검수 결과 반영)

원본(노드링크)이나 `env/yeouido/yeouido.net.xml` 을 직접 고치지 않는다. 검수로 확인한 것만
`yeouido/corrections.json` 에 적고, `yeouido/build_net.py` 가 마지막에 덧붙인다
(지금 지원: 회전 제한 지우기 `remove_turns`, 도로 삭제 `remove_links`, 새 도로 `add_links`, 차로 수 `lane_counts`, 좌회전·우회전 포켓 `turn_pockets`, 차로별 방향 `lane_moves`,
형식은 `yeouido/corrections.py` 설명). 보통은 카드의 버튼·단축키로 고친다. 파일을 편집기로 직접 고쳐 저장해도 서버가 1~2초 안에 알아채고
반영본을 다시 만들며(5~10초), 열려 있는 카드 화면도 새로고침 없이 "수정 후"로 다시 그린다.
JSON 문법 오류(몇째 줄)나 도로망을 만들지 못한 이유는 위쪽 줄에 나오고, 고쳐서 다시 저장하면 된다.
직접 고친 항목은 반영이 안 돼도 목록에서 빼지 않는다 (이유만 표시). 저장한 뒤 다시 만드는 동안은 버튼을 누르지 않는다.
목록이 비면 원래 도로망과 같고, `--no-corrections` 로 끌 수 있다.

**눈으로 확인**: 수정 목록이 있으면 서버가 수정 후 도로망(`inspection/out/compare/new.net.xml`)을 만들고,
카드 화면 왼쪽 SUMO 그림 위에 **[원래 | 수정 후]** 전환이 생긴다 (처음에는 "수정 후"로 열림, `V` 키로 번갈아 보기, 주소 `?v=base` 로 원래부터 열기).
목록 필터 "수정 목록에 있는 곳"으로 고친 곳만 모아 보고, 카드에는 "수정 후" 차로 화살표가 같이 나온다.
sumo-gui 로 보려면 `$SUMO_HOME/bin/sumo-gui -n inspection/out/compare/new.net.xml`
(수정 전은 `base.net.xml`).

수정한 뒤에는 전후 비교 보고서로 수정한 곳 밖이 바뀌지 않았는지도 본다.

보고서가 괜찮으면 `python -m yeouido.run_all --skip-validate` 로 env 파일을 다시 만든다
(교통 수요·워밍업 상태도 새 도로망에 맞게 다시 만들어진다).

## 파일

|---|---|
| `serve.py` | 로컬 서버, 기록 저장 API, VWorld 키 전달 |
| `export_cards.py` | 교차로·도로 구간 카드 자료 (구조·힌트·위치 보정값) → `out/cards.json` |
