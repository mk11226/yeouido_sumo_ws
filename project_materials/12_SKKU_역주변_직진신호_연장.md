# 성균관대역·구반포역 주변 직진 신호 연장

> 후속 변경: [13번 문서](13_SKKU_정체수준_주변교통_차로변경.md)에서 역 주변 약 200초 정지 목표, 본선 교통 증가, 정체 시 차로 변경을 반영했다. 아래 수치는 이전 설정이다.

2026-09-28. 양방향·교차로 주변 교통을 추가한 후 대기가 긴 역 주변 교차로의 직진 녹색을 늘렸다. 실제 현장 신호 시간표가 아닌 시뮬레이션 조정값이다.

| 위치 | 직진 녹색 변경 | 전체 주기 |
|---|---|---|
| 구반포역 서쪽 신반포로 | 40 → 60초 | 90초 유지 |
| 구반포역 서쪽 동작대로 접속부 | 25 → 45초 | 90초 유지 |
| 구반포역 남쪽 동작대로 | 40 → 60초 | 90초 유지 |
| 성균관대역 북쪽 서부로 | 40 → 60초 | 90초 유지 |
| 성균관대역 앞 서부로 연속 두 직진 | 각각 10 → 20초 | 90초 유지 |

총 신호 제어기 5개에서 직진 단계에 시간을 더 배분했다. 서울→수원 경로의 실제 직진 연결에서 녹색인 단계를 찾아 늘렸다. 같은 단계에 포함된 다른 통행 방향도 함께 연장되며, 직진 신호를 새로 켜거나 상충 방향을 동시에 녹색으로 만들지는 않는다.

황색 3초와 전체 적색 2초, 기존 신호 상태 문자열, 전체 90초 주기는 유지한다. 남은 녹색 시간은 교차 방향에 기존 비율대로 배분하며 단계당 최소 5초를 보장한다. 2단계 교차로는 60초/20초, 3단계 접속부는 45초/15초/15초, 성균관대역 앞 6단계 제어기는 두 직진 각 20초와 나머지 각 5초다. 교차 방향의 처리 용량은 감소하므로 실제 운영 신호 최적화 결과로 해석하면 안 된다.

구반포역 바로 앞 신호는 이미 대부분의 주기에서 직진 녹색이므로 그대로 두고, 서쪽 대기 구간과 이어지는 남쪽 교차로를 조정했다.

### 최초 시도와 수정 이유

처음에는 교차 방향의 녹색을 유지하면서 직진을 늘려 전체 주기가 110~130초가 되었다. seed 42에서 역 반경 600m 내 ego 정지 시간이 구반포역 **963.5→1,171초**, 성균관대역 **1,113.5→1,444.5초**로 오히려 늘었다. 따라서 이 설정은 채택하지 않았다. 해당 결과는 [첫 검사 폴더](../results/skku_commute/station_signals_seed42/)에 보존했다.

현재 설정은 전체 주기를 90초로 유지한 재배분 방식이다. 아래 최종 검사 결과는 이 설정을 기준으로 한다.

## 적용 방식

- [build_skku_station_signals.py](../build_skku_station_signals.py)가 원래 네트워크의 신호를 복사해 직진 녹색을 늘리고 남은 녹색 시간을 교차 방향에 배분한다.
- [station_signals.add.xml](../env/skku_commute/station_signals.add.xml)에 `station_straight_priority` 프로그램으로 저장하고 SUMO 설정에 추가했다. [SUMO 공식 문서](https://sumo.dlr.de/docs/Simulation/Traffic_Lights.html#defining-new-tls-programs)의 additional-file 프로그램 로딩 방식을 사용한다.
- [station_signals.manifest.json](../env/skku_commute/station_signals.manifest.json)에 신호 ID, 단계 번호, 접근 도로, 변경 전후 시간을 기록했다.
- 전체 구축 코드에도 생성 단계를 연결해 재구축 후 유지되도록 했다. 도로 네트워크와 차량 수요 파일은 변경하지 않았다.

## 실행

열려 있는 SUMO 창을 닫고 다시 실행한다.

```bash
python3 run_skku_commute.py --gui --background --viewport-m 800 --keep-open
```

## 검증

추가 프로그램 5개가 SUMO에서 실제 활성화되는지 확인했다. 기존 단계별 신호 상태와 황색·전체 적색 시간이 동일한지도 확인했다. 신호 주기·안전 간격 검사를 포함한 자동 검사 8개와 전체 주행 검사 후, 변경 전후 역 반경 600m 내 ego 정지 시간을 비교했다. 정지는 궤적의 속도 0.1m/s 미만 표본을 합산하며, 여러 번의 신호 대기와 앞차에 의한 대기를 함께 포함한다. seed 하나의 비교를 실제 도로의 평균 개선율로 해석하면 안 된다.

### 최종 결과: 90초 주기 재배분, seed 42

| 지표 | 신호 변경 전 | 최종 설정 |
|---|---:|---:|
| 구반포역 반경 600m 내 ego 정지 시간 | 963.5초 | 68초 |
| 성균관대역 반경 600m 내 ego 정지 시간 | 1,113.5초 | 10초 |
| ego 전체 주행 시간 | 8,518초 | 4,923초 |
| ego 충돌 / 전체 teleport | 0 / 0 | 0 / 0 |
| 배경 차량 충돌 보고 | 12건 | 6건 |

최종 ego는 38.34km를 완주했다. 주행 시간은 출발 전 300초 교통 형성 시간을 제외한다. 동일 seed와 동일 도로·수요 파일을 사용했고, 파일 해시로 확인했다. 배경 차량 충돌은 아직 남아 있으므로 전체 시뮬레이션 무충돌 검증으로 보지 않는다. 검사 종료 시각도 달라 충돌 건수의 단순 비교를 충돌률 개선으로 해석하면 안 된다.

신호 상태·황색·전체 적색·90초 주기 보존을 포함한 자동 검사 8개가 통과했다. 실제 SUMO에서 5개 추가 프로그램의 활성화와 90초 주기도 확인했다. 이번 결과는 seed 42 한 번의 비교이며, 교차 방향 대기나 다른 교통 시드까지 최적화한 결과는 아니다.
