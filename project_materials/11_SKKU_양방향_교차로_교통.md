# SKKU 서울→수원: 양방향·교차로 주변 교통

> 후속 신호 조정: [12번 문서](12_SKKU_역주변_직진신호_연장.md)에 성균관대역·구반포역 직진 시간 연장을 기록했다. 아래 주행 수치는 신호 연장 전 결과다.

2026-09-28. 기존에는 ego와 같은 방향으로 가는 구간 수요와 해당 경로로 들어오는 합류 수요가 대부분이었다. 반대편 차로와 교차로의 다른 도로에도 차량이 나타나도록 배경 수요를 확장했다.

## 추가한 흐름

- **반대 방향 14개 경로:** 기존 약 5km 구간의 양 끝에서 가까운 반대 방향 도로를 찾고, SUMO의 승용차 통행 가능 연결로 경로를 계산한다. 기존 방향과 같은 구간별 수요를 적용한다.
- **교차로 주변 150개 경로:** 양방향 경로에 접한 교차로에서 직진·회전 흐름을 만든다. 접근로별 최대 두 방향으로 수요를 나누고, 교차로 앞뒤 약 650m씩 연결을 연장한다. 가능하면 진행 방향이 이어지는 도로를 택하고 U턴·순환 경로를 피한다.
- 신호 교차로를 먼저 선택하고 선택 지점 사이에 400m 간격을 두어 가까운 교차로마다 차량이 중복 생성되는 것을 줄인다.
- 교차로 수요는 접근·진출 도로의 차로 수(최대 3차로)와 서울/남쪽 구간에 따라 조정한다. 서울은 접근로당 기본 45대/시간×차로 수, 남쪽은 30대/시간×차로 수이며 선택한 방향들로 나눈다.
- 새 반대 방향·교차로 차량은 추종 시간 간격 `tau=1.8`, 교차로 양보 시간 `jmTimegapMinor=2`, 추가 간격 `jmExtraGap=2`를 적용한다. 이 교차로 양보 설정은 새 주변 차량 유형에만 적용한다.
- 주변 경로들이 겹치는 각 도로에 추가 교차로 수요 합계 **차로당 최대 60대/시간**의 상한을 적용한다. 한 경로는 통과하는 도로 중 가장 혼잡한 곳의 비율에 맞춰 줄인다. 기존 본선·반대 방향·톨게이트 수요는 이 상한과 별도로 유지한다.
- 기존 서울 정체·의왕톨게이트 수요, 여섯 요금소 배분과 4→6→4 합류 설정은 유지한다. 배경 차량도 도로 연결과 SUMO 신호·안전 제어를 따른다.

현재 총 192개 배경 경로이며, 전체 생성률 합계는 약 9,885.56대/시간이다. 이는 약 38km 주변에 분산된 모든 출발 수요의 합계로, 어느 한 도로의 교통량을 뜻하지 않는다. 도로마다 실제 신호와 차로 수, 합류·대기 상태가 달라 양쪽 차량 수가 항상 같지는 않다.

실측 교통량이나 실제 출퇴근 OD 자료를 보정한 결과는 아니다. 보관된 지도 범위 내의 연결 가능한 주변 도로에 합성 교통을 추가한 것이다. 지도 밖의 도로나 모든 골목에 차량을 생성하지는 않는다.

## 차로 변경·도착 판정 보완

차량이 늘어난 뒤 기존 3초 연속 차로 변경 중 톨게이트 진입부에서 측면 충돌이 관측되었다. 전체 차량 유형에 `lcAssertive=0.5`를 적용해 차로 변경 시 요구하는 안전 간격을 늘렸다. 연속 차로 변경 시간, 요금소 배정과 정차 시간, 4→6→4 연결은 유지한다. 충돌 검사를 끄거나 차량을 강제로 차로에 옮기지는 않는다. 매개변수 의미는 [SUMO 안전 문서](https://sumo.dlr.de/docs/Simulation/Safety.html)의 차로 변경 설명을 따른다.

검사 코드에는 충돌로 제거된 ego가 SUMO의 도착 ID 목록에도 들어가면 `arrived`로 기록되는 문제가 있었다. `run_skku_commute.py`에서 **ego 충돌 판정을 도착 판정보다 먼저 수행**하도록 수정했다. 이전 검사 폴더 `balanced_seed42`의 `arrived` 표시는 완주 성공이 아니다. 그 검사에서는 약 30.21km 지점에서 ego가 충돌했고 `ego_collision=true`로 기록되어 있다.

## 실행

기존 SUMO 창을 닫고 다시 실행한다. 주변 교통을 보려면 `--background`가 필요하다.

```bash
python3 run_skku_commute.py --gui --background --viewport-m 800 --keep-open
```

교통을 300초 먼저 형성한 뒤 빨간 ego가 출발한다. 주변 교통으로 주행 시간이 늘어 실행기·SUMO 설정·수요 종료 시간을 기존 7,200초에서 10,800초(3시간)로 늘렸다. ego가 도착하면 그 전에 검사가 끝나며 `--keep-open`으로 GUI를 남길 수 있다. 주변 교차로를 넓게 보려면 800m, 차량의 차로 변경을 자세히 보려면 400m 화면 범위를 사용한다.

## 코드와 검증 자료

- [수요 생성 코드](../build_skku_commute.py)의 `area_traffic()`에서 반대 방향·교차로 경로를 만들고 `make_demand()`에서 기존 수요와 함께 저장한다.
- [현재 경로·교통량 목록](../env/skku_commute/manifest.json)의 `background.routes`와 [SUMO 수요](../env/skku_commute/skku_commute.rou.xml)에 반영했다.
- [검사 코드](../tests/test_skku_traffic.py)는 추가 경로가 ego 외 도로를 포함하는지, 모든 연결에서 승용차 통행이 가능한지, 순환 경로가 없는지, 톨게이트 여섯 차로 배분이 유지되는지 확인한다.
- [검증 폴더](../results/skku_commute/area_traffic_validation/)에 변경 전 수요·manifest와 새 주행 결과를 보관한다. 기존 10번 문서의 완주 시간은 이번 배경 수요 확장 전의 결과다.

## 조정 과정과 검증 해석

- 처음 교차로 수요를 추가한 검사에서는 2시간 제한에 도달해 수원 성대 도착 전에 종료됐다. 이후 교차로 유입량을 줄이고 배경 차량의 양보 간격을 늘렸다.
- 제한을 3시간으로 확대한 중간 설정 `extended_seed42`에서는 ego가 38.34km를 9,056초 동안 주행해 도착했다. 이 결과는 도로별 추가 교통량 상한과 전체 차량의 차로 변경 간격 보완 전 결과다. 배경 차량 충돌 보고도 있어 무충돌 검증으로 해석하면 안 된다.
- `balanced_seed42`에서는 도로별 수요 상한을 적용했지만 ego 측면 충돌이 발생했다. 이 검사를 계기로 차로 변경 안전 간격과 도착 판정을 보완했다.
- 최종 설정은 `conservative_seed42` 결과를 기준으로 한다. 중간 검사 결과나 변경 전 톨게이트 검증 수치를 최신 설정의 결과로 혼용하지 않는다.
- 자동 검사 6개는 건물 형상, 추가 경로의 합법적 차로 연결·순환 여부, 도로별 추가 교통량 상한, 톨게이트 여섯 차로 배분을 확인한다. 이 검사 통과가 모든 교통 시드에서의 무충돌을 보장하지는 않는다.

## 최종 검사 결과: seed 42

[주행 요약](../results/skku_commute/area_traffic_validation/conservative_seed42/summary.json) · [유형별 실제 차량 수·충돌 기록](../results/skku_commute/area_traffic_validation/audit.json)

- ego는 약 **38.34km를 8,518초(2시간 21분 58초)** 동안 주행해 수원 성대에 도착했다. 출발 전 교통 형성 시간은 별도다.
- ego 충돌 0, 전체 teleport 0. 반대 방향 차량 **4,387대**, 교차로 주변 차량 **9,965대**가 실제로 출발한 것을 tripinfo에서 확인했다. 이 숫자는 전체 검사 기간의 합계이며 화면에 동시에 보이는 차량 수가 아니다.
- **배경 차량 충돌 보고는 12건** 남았다. 교차로 7건과 톨게이트 진입부 측면 충돌 5건이다. 따라서 ego 완주와 교통 생성은 확인했지만 전체 교통의 무충돌 검증에는 통과하지 못했다. 충돌 차량은 SUMO의 기존 `collision.action=remove` 설정에 따라 제거된다. 충돌 제거 차량은 유형별 결과의 정상 도착 수에서 제외했다.
- 다음 보완 대상은 충돌이 반복되는 두 교차로의 내부 연결·신호 양보 관계와 톨게이트 진입부 연속 차로 변경이다. 단순히 차량 간격을 늘리는 것만으로 배경 차량 충돌이 모두 해결되지는 않았다.
- 기존 문서의 무충돌 수치는 이 수요에 적용할 수 없다. [실험 목록](../results/skku_commute/experiment_index.json)에도 ego 완주와 전체 교통 검사 실패를 구분해 기록했다.
